# learn-git

> A hands-on, browser-based platform to learn Git by **actually using it** — not by reading about it.

Students register, get an isolated terminal in the browser, and complete 30 real Git tasks — each validated against their actual repository state. No simulations. No multiple-choice. **Real git commands. Real feedback.**

---

## ✨ Features

- **30 structured tasks** across 4 difficulty tiers (Beginner → Expert)
- **Isolated per-student terminals** — every student gets their own container with a private Git repo (with a 1-click 'Factory Reset Repo' for when they get stuck)
- **Internet-blocked workspaces** — students can only interact with the built-in internal git-server; no external access
- **Live task validation** — the platform runs `git` commands inside each container to check real repo state
- **Progress persists** — data is stored in Docker named volumes; `docker compose down` never wipes student work
- **Admin dashboard** — Grafana-style UI to view all students' progress, stop idle terminals, reset passwords, and monitor live memory/CPU per container
- **Resizable split-panel UI** — drag the divider between the task list and terminal to resize
- **Idle reaper** — containers idle beyond a configurable threshold are automatically stopped (data preserved)

## 🏗 Architecture

```
Browser
  │
  └─► caddy (ports 80/443)
        ├─► /           → webapp  (React/Vite — task UI)
        ├─► /api/       → api     (FastAPI — auth, tasks, validation)
        └─► /terminal/  → workspace-<reg_no>  (ttyd — per-student shell)

Internal (no internet):
  api ──► workspace containers  (Docker-in-Docker via socket)
  workspace containers ──► git-server  (git:// protocol, internal only)
```

| Service | Image | Role |
|---|---|---|
| `caddy` | `caddy:alpine` | Reverse proxy, handles TLS and dynamic routing |
| `webapp` | Custom (Node+Vite builder -> nginx) | Task list UI, login, admin dashboard |
| `api` | Custom (Python/FastAPI/SQLAlchemy) | Auth, task engine, workspace manager |
| `git-server` | `alpine` + git-daemon | Internal bare repos for remote tasks |
| `workspace-<reg_no>` | Custom (alpine+ttyd+git) | One isolated container per student |

## 🚀 Quick Start (Local / Testing)

> For a production deployment with HTTPS and a real domain, see [DEPLOYMENT.md](DEPLOYMENT.md).

**Prerequisites:** Docker installed and running.

```bash
git clone <this-repo-url>
cd learn-git
python3 server.py
```

`server.py` handles everything automatically:
- Creates `.env` from `.env.example` with a real random `SECRET_KEY`
- Creates the `students-data/` directory
- Builds the workspace image
- Starts the full stack

Open **http://localhost** when it's ready.

To stop:
```bash
python3 server.py --down
```

To start with live logs:
```bash
python3 server.py --logs
```

## ⚙️ Configuration (`.env`)

Copy `.env.example` to `.env` and edit before deploying:

| Variable | Description | Default |
|---|---|---|
| `SECRET_KEY` | Signs session cookies — use a long random string | *(auto-generated by server.py)* |
| `ADMIN_REG_NOS` | Comma-separated reg nos that get admin rights on sign-up | *(empty)* |
| `CORS_ORIGIN` | Restrict CORS to your frontend origin in production | `*` |
| `COOKIE_SECURE` | Set `true` when serving over HTTPS | `false` |
| `WEB_CONCURRENCY` | Number of gunicorn workers for the API | `4` |
| `IDLE_WORKSPACE_HOURS` | Hours idle before a workspace container is auto-stopped | `24` |

## 📚 Task Curriculum (30 Tasks)

### 🟢 Beginner (8 tasks)
1. Initialize a repository
2. Make your first commit
3. Make a second commit
4. Understand repository status
5. Ignore files with `.gitignore`
6. View the commit history
7. Inspect staged changes before committing
8. Inspect a specific commit

### 🔵 Intermediate (12 tasks)
9. Create a branch named 'dev'
10. Switch to the 'dev' branch
11. Merge 'dev' into 'main'
12. Amend the last commit
13. Stash your changes
14. Retrieve stashed changes (`stash pop`)
15. Rename a branch
16. Tag a release point
17. Create multiple tags
18. Delete the 'dev' branch
19. Blame a file (`git blame`)
20. Summarize history with `git shortlog`

### 🟣 Advanced (6 tasks)
21. Rebase a branch onto main
22. Revert a commit safely
23. Cherry-pick a single commit
24. Hard reset to a previous commit
25. Interactive rebase to clean history
26. Write a conventional commit message (`feat:`, `fix:`, etc.)

### 🟠 Expert (4 tasks)
27. Clone from the practice remote (internal git-server, no internet)
28. Push commits to the remote
29. Pull updates from the remote
30. Resolve a merge conflict

## 🔐 Security Notes

- Student workspace containers are placed on an **internal Docker network** with no outbound internet access
- They can only reach the built-in `git-server` container for remote tasks
- Sessions are signed with `SECRET_KEY` — keep this secret and rotate it if compromised
- See [SECURITY.md](SECURITY.md) for full threat model and hardening guidance
